# jj-agent 维护者标准（审查必读）

适用仓库：`good-night-oppie/jj-agent`（哔站切片助手）。记录日期 2026-10-31。
来源：`reference/ADR-001`、`ADR-002`、`ADR-003`、`VERIFICATION.md`、
`LICENSES.md`、`.github/workflows/tests.yml`，以及 QQ（首席代码审查员）在
PR #2、#3、#5、#10、#12 评论里反复执行的审查红线。与更早的单条评论冲突时，
以本文件为准；本文件与 ADR 冲突时，以 ADR 为准并修订本文件。

## 1. 红线（每条都是具体检查，不是感觉）

逐条核对，命中任何一条即为「确认的 bug」，阻塞合并。

1. **本地服务只监听 127.0.0.1。** `scripts/app_server.py`、`scripts/run_app.py`
   里的监听地址不能变成 `0.0.0.0`、空字符串或主机名；Host/Origin 检查
   （只接受 `127.0.0.1:<port>` / `localhost:<port>`）不能放宽；启动令牌仍放在
   网址 `#` 之后，不进查询串、不进日志。
2. **路径不能拼到文件夹外。** 任何由页面、项目文件、弹幕 XML、模型或外部
   输入给出的文件名/相对路径，必须解析后仍位于用户选定的录像文件夹或导出
   文件夹之内（`..`、绝对路径、盘符、符号链接/目录联接都要拒绝）。看
   `os.path.join` / `Path /` 的右操作数来自哪里。
3. **ffmpeg / ffprobe 参数用数组，不经 shell。** `subprocess.run([...])`，
   没有 `shell=True`，没有把用户字符串拼进一个命令行字符串；滤镜串里来自
   用户的文本（字幕、弹幕）必须转义。
4. **不覆盖已有文件。** 导出、项目保存、打包、移动草稿都用「目标已存在就失败」
   的方式（`open(..., "x")`、`os.rename`/`os.link` 到不存在的名字、
   `renameat2 NOREPLACE`），不能用 `os.replace`、`shutil.copy` 覆盖；半成品
   必须留在暂存目录并在失败时清掉，最终目录原子发布。
5. **模型 / 外部输入给的路径、URL、命令不直接执行。** AI 起名、弹幕、项目
   文件、录播姬 XML 的内容只能当数据；不能据此 `open()`、`subprocess`、
   `webbrowser`、`os.startfile`。XML 解析拒绝 DOCTYPE/ENTITY。
6. **默认零网络。** 唯一例外是主播自己设置的 AI 起名 / 挑成片，而且只发
   打码后的弹幕文字，不发音视频、昵称、账号、路径。新增 `urllib`/`http.client`
   /`socket` 调用、新增运行时下载（模型、字体、更新）都是红线；
   `test_page_has_no_external_urls` 一类守护测试不能被删或放宽。
7. **日志、报告、回执、错误文字里不出现**：密钥 / token、账号、
   机器用户名或含用户名的绝对路径、观众昵称。弹幕画进视频时只画文字；
   醒目留言卡片默认隐藏昵称（PR #8）。
8. **听写不加载 PyAV**（ADR-002，决策 5）。导入 faster-whisper 前的替身不能
   被绕过；`tests/test_no_pyav.py` 不能被删或跳过。
9. **clean-room。** 实现侧只能引用净化后的 SPEC.md 及其 examples；任何引用、
   复制、改写 `reference/capcut-investigation/` 下内容的改动一律打回，
   包括提示词、技能、测试语料、注释。审查者自己也不打开那个目录。
10. **发布包只装允许名单里的东西**（ADR-003 D3，PR #7）：路径任一段以 `.`
    开头的、`experiments/`、`reference/`、`.git`、目录联接都不进包；
    `check_result` 反向检查名单外文件即打包失败。`licenses/GPL-3.0.txt`
    的 SHA-256 校验不能去掉。
11. **对主播的文字用白话。** 界面和错误提示不出现路径、命令、英文术语、
    堆栈；每个错误写清原因和下一步，并说明录像有没有被改动。
    `scripts/friendly.py` 的正则只取数字，不拼路径。

## 2. 审查顺序

1. 先弄清 PR 做什么、改了哪些文件、哪些是高风险文件
   （`scripts/clip.py`、`scripts/project.py`、`scripts/app_server.py`、
   `scripts/run_app.py`、`scripts/build_package.py`、`scripts/package_check.py`、
   `scripts/ai_editor.py`、`scripts/recorder.py`、`app/app.js` 里的保存 / 发送 /
   密钥逻辑）。复审时先把上一轮每条意见对到新提交的位置。
2. 逐条过第 1 节红线。
3. 再看正确性：剪辑点、音画同步、撤销 / 重做、半成品清理、Windows 路径
   （NTFS 不允许的文件名、管理员权限下的 ACL 继承）、FLV 开头 / 采样率变化
   等已知坑（见 VERIFICATION.md 对应小节）。
4. 再看测试（第 3 节）和描述里的证据（第 4 节）。
5. 最后给结论（第 5 节）。

## 3. 测试标准

- 两条命令必须在当前 head 上跑过并给出数字：
  `python3 -B -I -m unittest discover -s tests -v` 和 `ruff check .`。
  「Ran N tests … OK (skipped=K)」要写 N 和 K；跳过的要说原因（跳过不等于
  通过）。没跑的写「没跑」，不写「应该没问题」。
- 每个新测试要能说出「改回旧代码它就会红」。只测接口存在、只测 mock 被
  调用、只断言形状不断言值的测试不算覆盖。
- 改剪辑 / 导出 / 预览的 PR（`clip.py`、`project.py` 的导出路径）必须跑
  **合成闪光 + 提示音的音画同步检查**，每个接缝的读数与逐段基线之差
  **不超过 40 ms**，FLV 与 MP4 源都要有读数（PR #5 的做法）。没有读数就是
  「要改」，不是备注。
- 测试只用程序现做的合成素材；不把真实录像、弹幕、昵称、cookie 放进仓库。
- CI 以 `tests / linux (ubuntu-24.04)`（FFmpeg 6.1）为必须通过；
  `ubuntu-latest` 只报告不拦截（ADR-003 D2，T16 之前）。Windows 没有 CI，
  Win11 结果要在描述里写明是哪台机器、哪份 FFmpeg（`BILI_CLIP_FFMPEG_DIR`
  指向发布包时写明 n9.0.2 和两个 exe 的 SHA-256）。

## 4. 描述里必须有的证据

- 改动范围与 head 一致；叠在别的 PR 上时写明合并顺序。
- 测试命令、数字、平台、没跑的项（第 3 节）。
- 导出相关：音画同步读数（第 3 节）；估算类改动（磁盘空间、码率系数）
  写明实测来源和一次测量的局限。
- **新增或升级第三方组件**：许可证类型、来源 URL、版本、下载产物的 SHA-256，
  同时写进 `LICENSES.md` 和随包的 `第三方组件许可.txt`；GPL / 不明许可的
  组件不进包（FFmpeg 只用 LGPL 构建，`--enable-gpl`/`nonfree` 一律拒绝）。
- 对主播可见的文字改动，贴出最终文案。

## 5. 结论怎么写

- 结论只有三种：**通过** / **要改** / **需要讨论**（设计或产品决定只能由
  主人或 Deja 拍板时用）。
- 每条问题写三样：`文件:行号`；`具体输入 → 错误结果`；`建议改法`。
- 把问题分成「**确认的 bug**」（自己从代码推出来了触发条件，或者跑出来了）
  和「**可能有问题**」（缺证据、依赖运行时事实，不阻塞）。
- 结尾按三分写：**看到的事实**（读过 / 跑过的）、**推断**、**还不知道的**。
- 先写「我跑了什么 / 没跑什么」。只有具体 bug 阻塞；要更多测试、基准、
  真人试用属非阻塞备注，而且同一证据不重复要。
- 复审时逐条对上一轮意见：已改（位置）/ 仍在 / 不再适用。
- 对主播的文字用白话；给维护者的用中文，代码标识符、路径、命令保持原样。
  不写寒暄、不复述 diff、不加「总的来说」。
